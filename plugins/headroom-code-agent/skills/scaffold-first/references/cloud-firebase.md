# cloud-firebase scaffold-first reference (researched 2026-08-30)

Covers **Firebase**. Verified live this session on Christopher's real account (CLI 15.28.1 via Homebrew, signed in as christopher@digital1group.com; three live projects observed). Same cloud rule: **reads and LOCAL emulators are free game; deploys, provisioning (Cloud SQL, Firestore databases), and anything touching the live projects need Christopher's explicit go.**

## The agent path (checked live)

The **Firebase MCP plugin** is installed and is the official agent surface — it wraps the CLI:

- `firebase_get_environment` — ALWAYS first: shows the signed-in user, the active project directory, and the active project. This session it exposed that the default directory was the repo root with no firebase.json.
- `firebase_update_environment` — point `project_dir` at the actual app directory before any init/deploy.
- `firebase_list_projects` — live projects: `d1-admanagement`, `d1-identity`, `foresite-834aa`. All real; treat as production.
- `firebase_init` — non-interactive init (the CLI's own `firebase init` is interactive; the MCP tool is the unattended path). Run live with `{hosting: {...}}`: wrote `firebase.json` + populated `public/`, local files only.

## The no-cost verification loop (run live)

```bash
firebase emulators:start --only hosting --project demo-scaffold
```

Served the hosting content locally (see Traps for the port). A `demo-*` project id keeps the emulator fully offline — it never contacts a real project. This is the verification path for Firestore/Auth/Functions work too (`--only firestore,auth,functions`); emulator suite first, deploy only after Christopher's go.

## What needs Christopher's explicit go

- `firebase deploy` in any form (hosting, rules, functions) — it changes live sites/projects.
- `firebase_init` features that provision cloud resources: `dataconnect` with `provision_cloudsql: true` (creates a Cloud SQL instance), `firestore`/`database` pointed at a real project, `auth` provider changes.
- Creating projects/apps (`firebase_create_project`, `firebase_create_app`).

## Never hand-write

- `firebase.json`, `.firebaserc`, `firestore.rules` / `database.rules.json` / `storage.rules` skeletons — generated by init; edit rules content in place afterward (rules are code you own; the files' existence and wiring are init's).

## Traps

**macOS takes port 5000, so the hosting emulator silently moves to 5002.** The log says so in one easy-to-miss line; a curl to 5000 gets nothing and looks like failure. Read the emulator log for the actual port. (Observed 2026-08-30.)

**The MCP's default project directory is wherever the session started** — this session it pointed at the FairStandard repo root. An init run without `firebase_update_environment` first would have written firebase.json into the wrong tree. Environment check first, always. (Observed 2026-08-30.)

**`firebase init hosting` overwrites an existing `public/index.html`** with its own welcome page — don't stage real content before init. (Observed 2026-08-30.)

**The Homebrew CLI trails npm by a patch** (15.28.1 vs 15.28.2 at this check) — fine day-to-day; `npx firebase-tools@latest` when a fresh fix matters.
