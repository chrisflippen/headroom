# tauri scaffold-first reference (researched 2026-08-30)

Covers desktop apps with **Tauri 2** — the Rust-backed alternative to Electron with a system-webview shell. Scaffolder: **create-tauri-app**, run live on this machine (macOS arm64, Node v26.7.0, npm 11.19.0, rustc 1.91.1): scaffolded with the `svelte-ts` template, compiled, and launched to a real rendered window whose full content was verified through the macOS accessibility tree. Read `references/electron.md` for the Electron side of the desktop decision.

## Official setup commands

| Step | Command | What it generates |
|---|---|---|
| Scaffold | `npx create-tauri-app@latest <dir> --template svelte-ts --manager npm --identifier com.<org>.<app> -y` | a SvelteKit-style frontend (`src/`, `svelte.config.js`, `vite.config.js`, `tsconfig.json`) plus `src-tauri/` (`Cargo.toml`, `tauri.conf.json`, `build.rs`, `capabilities/`, `icons/`, Rust `src/`) |
| Help / template list | `npx create-tauri-app@latest --help` | prints flags and all 18 templates |
| Install + first run | `npm install`, then `npm run tauri dev` | compiles the Rust side (347 crates, ~70s on this machine after downloads) and opens the app window with Vite hot reload |
| Add mobile targets later | `npm run tauri ios init` / `npm run tauri android init` | printed by the scaffolder itself as the official next step; not run this session (see gaps) |

Verified versions at this check (`npm view <pkg> version` / observed in the compile log): `create-tauri-app@4.6.2`, `@tauri-apps/cli@2.11.4`, `tauri` crate 2.11.5. Templates from the tool's own help: `vanilla`, `vanilla-ts`, `vue`, `vue-ts`, `svelte`, `svelte-ts`, `react`, `react-ts`, `solid`, `solid-ts`, `yew`, `leptos`, `sycamore`, `angular`, `preact`, `preact-ts`, `blazor`, `dioxus`. `--tauri-version` pins major 1 or 2 — leave it alone to get latest stable.

The scaffold is genuinely non-interactive with `-y` plus explicit `--template`, `--manager`, and `--identifier` (verified with stdin closed, exit 0) — no prompt-stream tricks needed, unlike electron-vite's creator.

## Choosing (vs Electron)

- **Tauri** ships a Rust binary that renders in the OS webview (WKWebView here) — much smaller apps, no bundled Chromium, and the backend language is Rust. The toolchain cost: a working Rust install and a first compile measured in minutes, and the webview differs per OS (Safari-engine quirks on macOS, WebView2 on Windows).
- **Electron** bundles Chromium+Node — identical rendering everywhere, JS on both sides, bigger installs. See `references/electron.md` for its scaffolder split and traps.
- Both offer Svelte templates; both booted verifiably on this machine. Frontend tooling generated by create-tauri-app is current (Vite 7, Svelte 5 — observed in the generated `package.json`), so there is no modernization debt like Electron Forge's.
- macOS-specific note observed live: Tauri compiled and ran with only Command Line Tools active (no full Xcode selected). Desktop Tauri does not need Xcode; Tauri **iOS** targets do.

## Verifying the app actually runs (macOS)

`tauri-driver` (Tauri's WebDriver layer) does not support macOS — per Tauri's own docs it covers Windows and Linux only, so there is no Playwright-style harness here like Electron's. What worked this session, in order of strength:

1. **Launch**: `npm run tauri dev` in the background, then confirm the log reaches `Finished \`dev\` profile` followed by `Running \`target/debug/tauri-app\``, and the process named after your app exists (`pgrep -fl <app-name>`).
2. **Render proof**: read the window's content through the macOS accessibility tree (any AX client; Ghost OS's `ghost_read` was used here). Observed the full expected template UI: "Welcome to Tauri + Svelte", the three logos, the name input, and the Greet button — that is the real window, not the dev server.
3. **Logic**: Rust commands (`#[tauri::command]`) are plain functions — test them with `cargo test` inside `src-tauri/`. The template ships none; add tests rather than relying on GUI-click verification.

Synthetic click/keystroke injection into the window proved unreliable here when another app held a modal (events land on the focused app — see Traps). Don't treat a failed synthetic click as a failed app; the AX read is the render check.

## Never hand-write

- `src-tauri/tauri.conf.json` skeleton, `src-tauri/Cargo.toml`, `src-tauri/build.rs`, and the `capabilities/` directory — all from `create-tauri-app`. Editing `tauri.conf.json` values and adding capabilities afterward is normal; typing the files from memory is not. Note: `src-tauri/Cargo.toml` is generated by create-tauri-app, NOT by `cargo new` — regenerate through the app scaffolder, and add crates with `cargo add` from inside `src-tauri/`.
- Frontend configs (`svelte.config.js`, `vite.config.js`, `tsconfig.json`) — the scaffolder writes Tauri-aware versions (fixed dev port 1420, HMR wiring); regenerating them with plain `sv create` would lose that.
- `package-lock.json`, `src-tauri/Cargo.lock`, `src-tauri/target/` — machine-owned as always.

## Thorough setup checklist

1. Rust first: `rustup update` so the toolchain is current before the first compile.
2. Scaffold with the full non-interactive command (template, manager, identifier, `-y`) — the identifier is baked into `tauri.conf.json` and is painful to change after signing enters the picture.
3. `npm install`, then `npm run tauri dev` once and wait out the first Rust compile; confirm the window content via an AX read, not just the log line.
4. `git init` yourself — the scaffolder does not create a repo (observed: no `.git` in the output).
5. Wire lint/format for both halves: the frontend per its framework's reference page, and `cargo fmt` + `cargo clippy` for `src-tauri` (see `references/rust.md`).
6. Add `cargo test` coverage for every `#[tauri::command]` as it appears — that is the only scriptable logic check on macOS.
7. For distribution, `npm run tauri build` produces the bundle; not exercised this session — verify it before relying on it, same rule as everything else.

## Traps

**npm 11's install-scripts gating warns on this scaffold too, but dev mode still worked.** `npm install` printed the by-now-familiar `install scripts not yet covered by allowScripts` warning (esbuild is in the tree), yet `npm run tauri dev` compiled and ran without intervention this session. Don't assume that generalizes — if Vite fails oddly after install, run `npm install-scripts ls` and approve before debugging anything else. (Recorded run: 2026-08-30.)

**Synthetic desktop input goes to the focused app, and something else may hold focus.** During verification, a System Settings modal held focus; typed text and Return keys silently went there instead of the Tauri window, which looked exactly like "the app ignores input." Check what actually has focus before concluding anything about the app — and prefer AX reads plus `cargo test` over GUI-event verification on macOS. (Recorded run: 2026-08-30.)

**First compile is minutes, silent-ish, and looks like a hang.** 347 crates on this machine before the window appears. The log keeps moving (`Building [====>  ] n/347`); read the log file, don't kill the process. (Recorded run: 2026-08-30, ~70s compile after crate downloads on an M-series machine — slower cold.)
